# 中国学术报告类型规范

> 仅在 [`academic-core.md`](./academic-core.md) 判定为学术任务时按需读取。
> 本文件决定内容职责、论证顺序和时间压缩，不替代院校/会议强制模板，也不改变
> Default、Quick、Beautify 的 Gate、保真边界或导出契约。

## 1. 路由与共通规则

按用户明确称谓优先；其次根据听众、阶段和材料判断。一个请求同时包含多种场景时，
选择本次实际汇报的主场景，其他场景作为约束。例如“把中期成果整理成预答辩”按
预答辩组织，但如实保留中期证据状态。

| 触发语义 | 报告类型 |
| --- | --- |
| 选题、开题、研究计划、proposal | 开题报告 |
| 中期检查、年度进展、阶段考核 | 中期报告 |
| 预答辩、预审、内部答辩 | 预答辩 |
| 毕业答辩、学位答辩、正式答辩 | 正式答辩 |
| 学术会议、论坛、口头报告、invited talk | 学术会议报告 |
| 组会、文献汇报、journal club、实验室进展 | 组会报告 |
| 项目验收、项目评审、基金申请/评审、课题评审 | 项目或基金评审 |

通用论证链为“问题与边界 → 已知证据与缺口 → 研究问题/目标 → 方法与可行性 →
结果或预期验证 → 局限/风险 → 结论与请求”。类型规范可以调整先后，但不得省略支撑
核心判断所需的环节。

时间压缩遵循：先删重复背景和装饰，再把细节移入附录；保留问题、差距、方法可信度、
决定性证据、局限和本次请求。不得通过缩小字号、加快到不可理解或删掉限定条件来
满足时长。

## 2. 开题报告

**目的**：证明问题值得研究、现有工作留下明确缺口、研究问题可回答、方案可执行，
并让专家能指出风险。

推荐顺序：

1. 题目、研究对象与一句话问题；
2. 背景与学术/应用意义，只保留导向问题的证据；
3. 国内外研究现状与比较矩阵；
4. 明确缺口、研究边界、研究问题（RQ）/假设；
5. 研究目标、内容与潜在贡献；
6. 理论框架、技术路线或研究设计；
7. 数据、样本、变量、实验/分析方法、评价指标与伦理/合规；
8. 可行性基础、预实验（如有）及其“非最终结果”状态；
9. 进度、资源、风险与替代方案；
10. 阶段结论及希望专家重点评议的问题。

**底线**：预期贡献不能写成已完成创新；预实验只能支持可行性，不得外推最终结论。
相关工作必须说明比较维度和来源，不能用文献数量代替研究缺口。

**压缩**：短报告优先保留问题/缺口、RQ、技术路线、验证方案、可行性和风险；背景、
逐篇综述、详细进度和参数表放附录。

**附录**：检索式与纳排标准、完整文献矩阵、变量/量表、样本量依据、实验参数、伦理
与数据管理、详细甘特图、风险备选方案。

## 3. 中期报告

**目的**：相对已批准目标说明实际进展、证据质量、偏差原因和后续可完成性。

推荐顺序：

1. 原批准目标、范围和里程碑基线；
2. 已完成/进行中/未开始的状态总览；
3. 数据、方法、系统或实验的实际完成情况；
4. 阶段结果与质量控制，区分观察与解释；
5. 与计划、基线或已有工作的比较；
6. 偏差、失败实验、复现问题和有效性威胁；
7. 已采取的修正、剩余风险与需要的支持；
8. 下一阶段工作、负责人和可核验里程碑。

**底线**：不能只报“完成率”；完成状态必须有工件或证据。计划调整要显示原计划、
变化、原因和影响。负结果不得隐藏，未完成不得包装为“基本完成”。

**压缩**：用一页“目标—证据—状态—偏差”总览替代流水账；重点保留决定能否按期
完成的证据与风险。

**附录**：版本记录、详细实验日志、失败案例、数据质量报告、变更审批、完整进度表。

## 4. 预答辩与正式答辩

两者共享“问题 → 贡献 → 方法 → 证据 → 边界 → 结论”的主链，但审查姿态不同。

### 4.1 预答辩

**目的**：尽早暴露论证断点、证据缺口、论文结构和答辩风险。

推荐顺序：研究问题与论文主张；相关工作和差距；贡献边界；方法与数据；主要结果；
消融/稳健性/对照；失败案例与威胁；尚未闭合的问题；修改计划与请专家重点评议项。

把“不确定、待补、可能被质疑”做成明确页面职责，不要模拟正式答辩的确定语气。

### 4.2 正式答辩

**目的**：让答辩委员会在限定时间内判断研究的原创性、规范性、证据充分性和贡献。

推荐顺序：

1. 封面与一句话研究主张；
2. 问题、意义和边界；
3. 相关工作与可验证的研究缺口；
4. 研究问题/目标及贡献概览；
5. 方法、数据、实验设计和合规；
6. 决定性结果、对照、消融、稳健性与误差分析；
7. 创新点逐项回扣证据；
8. 局限、适用范围和可复现性；
9. 结论与后续工作；
10. 可选的简短礼貌致谢。

**底线**：“创新点”必须对应已展示证据和明确比较对象。正式结论只覆盖数据支持的
范围。礼貌性“感谢各位专家，恳请批评指正”可以附在实质结论页，除非院校模板强制，
不单独占用一个信息为空的页面。

**压缩**：背景与综述只为研究缺口服务；把完整参数、补充实验、额外定理证明、伦理
文件和备用结果移入可快速定位的答疑附录。主报告优先保留贡献与决定性证据。

**答疑附录**：完整指标定义、数据划分、统计检验、超参数、额外基线、失败案例、
可复现性清单、伦理/隐私、论文发表状态、专家常问的边界问题。

## 5. 学术会议报告

**目的**：让领域同行快速理解一个清晰贡献、证据和可讨论的边界，而不是复述论文。

推荐顺序：问题钩子与 take-home message；现有方法的具体缺口；本工作一句话贡献；
方法直觉与必要技术细节；关键实验设计；二至三个决定性结果；与最相关工作的公平
比较；局限/失败案例；结论与讨论问题。

**底线**：保留论文题名、作者、机构、会议和发表状态的准确表述；尚未录用的工作
不得暗示已发表。复用论文图时保留图号/来源并确保许可或合理使用依据。

**压缩**：按分钟而非论文章节分配。五至十分钟只讲一个主贡献和一组核心证据；方法
细节与补充实验放备用页。跨学科听众先解释术语和任务，同行听众减少教科书背景。

**附录**：算法细节、证明、补充实验、数据声明、代码/材料链接、利益冲突与致谢。

## 6. 组会报告

组会先区分两种子类型：

### 6.1 文献汇报 / Journal Club

推荐顺序：文献元数据与研究问题；背景和定位；方法；主要结果；作者原结论；方法学
评价；可复现性与局限；与本组工作的关联；讨论问题。

明确区分“论文作者报告”“汇报者复现/计算”“汇报者评价”。图表逐页短引，备注给出
完整文献；不得把摘要措辞当作已独立验证的事实。

### 6.2 本组研究进展

推荐顺序：上次承诺与本次问题；本周期完成的工作；实验设置；结果与失败案例；解释
和备选解释；阻塞项；下一步最小可验证任务；需要团队决定/帮助的问题。

**压缩**：减少通用背景，保留实验设置、证据、异常和需要讨论的决策。组会不是成果
宣传，负结果与调试线索有直接价值。

**附录**：论文完整引用、逐实验配置、日志、额外图、代码提交/数据版本、待办清单。

## 7. 项目或基金评审

先区分申请/立项评审与执行/验收评审；不得把拟开展工作写成已取得成果。

### 7.1 申请或立项

推荐顺序：科学问题与必要性；国内外现状和缺口；总体目标与可检验指标；研究内容；
技术路线；创新点及比较对象；前期基础；团队与条件；计划和里程碑；预算逻辑；风险、
伦理和替代方案；预期成果与影响。

### 7.2 执行、结题或验收

推荐顺序：任务书目标；交付物与证据；指标完成情况；代表性成果；经费/资源使用的
可核验摘要；偏差与变更；影响和推广边界；遗留问题；验收请求。

**底线**：政策依据、行业数据、团队履历、论文/专利状态、预算、社会经济效益均需
来源或明确估算口径。申请人的目标、预测和测算标为“计划/估算”，不得伪装为外部
事实。项目指标使用任务书原口径，不能换一个更好看的分母。

**压缩**：申请评审优先“为什么值得投、为什么做得到、如何判断成功”；验收评审优先
“承诺了什么、交付了什么、证据在哪里、偏差如何处理”。

**附录**：任务书/指南对照、成果清单、证明材料、预算明细、伦理与数据治理、风险
登记、团队分工、合作单位承诺。

## 8. 通用学术报告回退

没有更具体类型时，使用：封面 → 问题与意义 → 相关工作/现状 → 目标或研究问题 →
方法与数据 → 主要证据 → 讨论与局限 → 结论与下一步/待评议问题。不要自动加入
“创新点”“技术路线”“致谢”等只属于部分场景的章节；根据材料和听众决定。
